# RUN-017 — Рабочий календарь и защищённое включение заявок (Pakkasukko)

## Изменения

- Свободные интервалы D1 теперь отображаются **всегда**, даже когда бронирование отключено. Не показываются чужие контактные данные, только дата, начало и конец свободного времени.
- Админка может добавлять открытые/заблокированные интервалы, просматривать расписание и экспортировать CSV. В ней появился раздел «Включение бронирования».
- Реальная отправка заявки отключена по умолчанию в отдельной таблице D1 `booking_settings`, независимо от наличия кода или опубликованного сайта.
- Включение возможно только после настройки **Turnstile + Resend**, успешного запроса пробного письма к Resend, подтверждения получения письма владельцем и подтверждения публикации политики конфиденциальности.
- Владелец может отключить приём немедленно без изменения кода или остановки показа свободных дат.
- Все изменения изолированы в `velardream-ctrl/pakkasukko` (preview), D1 `pakkasukko-db`, R2 `pakkasukko-preview-media`.

## Что нужно подключить для реальных заявок (один раз)

### Cloudflare Turnstile
Откройте [Cloudflare → Turnstile](https://dash.cloudflare.com/), создайте **новый** виджет `Pakkasukko Booking` с доменом `pakkasukko.velardream.workers.dev` и, после приобретения/настройки, `pakkasukko.fi`.
Скопируйте `sitekey` и `secret` **не в чат, а напрямую в настройки GitHub Actions secrets**.

### Resend
Откройте [Resend](https://resend.com/domains), подтвердите домен, с которого будет отправляться почта, и создайте ключ отправки. Адрес `FROM_EMAIL` должен принадлежать подтверждённому в Resend домену. `OWNER_EMAIL` — рабочий адрес, на который должны приходить заявки. Отсутствие собственного зарегистрированного домена пока блокирует использование неподтверждённого отправителя; не подменяйте его случайным адресом.

### GitHub Actions secrets
Перейдите в `https://github.com/velardream-ctrl/pakkasukko/settings/secrets/actions` и создайте **только в этом репозитории** пять secrets:
- `PAKKASUKKO_TURNSTILE_SITE_KEY` — публичный ключ виджета;
- `PAKKASUKKO_TURNSTILE_SECRET` — приватный ключ виджета;
- `PAKKASUKKO_RESEND_API_KEY` — приватный ключ отправки;
- `PAKKASUKKO_OWNER_EMAIL` — адрес для уведомлений;
- `PAKKASUKKO_FROM_EMAIL` — подтверждённый отправитель.

Секреты нельзя вставлять в публичный GitHub-код, чат или комментарии. При новом GitHub Actions деплое скрипт настроит соответствующие Worker bindings; существующие Worker secrets, не включённые в `--secrets-file`, Wrangler сохраняет. Актуальный конфиг Wrangler остаётся источником истины для общедоступных переменных.

Откройте `https://github.com/velardream-ctrl/pakkasukko/actions/workflows/pakkasukko-deploy.yml` и запустите **Run workflow** для ветки `preview` после добавления секретов. Только после успешного deploy появятся необходимые привязки.

### Контрольный запуск
1. Войдите в `https://pakkasukko.velardream.workers.dev/admin.html`.
2. Создайте свободный интервал в «Календарь и переезды»; убедитесь, что он появился на главной странице.
3. Убедитесь, что вы действительно опубликовали политику конфиденциальности, реквизиты организатора и сведения об обработке данных.
4. В разделе «Включение бронирования» нажмите «Отправить тестовое письмо владельцу». Это подтверждает лишь принятие сообщения сервисом, **не факт доставки**.
5. После реального получения письма и проверки политики поставьте две галочки, затем нажмите «Включить приём заявок».
6. Проверьте реальную форму с CAPTCHA, отправку тестовой заявки, приход уведомления, статус pending, ручное подтверждение, экспорт CSV, защиту от двойного подтверждения.

Не считайте бронирование подтверждённым после отправки: клиент должен дождаться личного согласования маршрута, времени и цены.

## Состояние после RUN-017
Публичный просмотр слотов работает без ключей. Реальная отправка остаётся **выключенной до прохождения контрольного списка**. Отсутствующие ключи нельзя создать из уже имеющегося токена Workers без отдельной авторизации для соответствующих сервисов.
