# RUN-012 — Устранение двойных фотографий

## Причина
При выборе фотографии для раздела `top` через «Содержание страницы» редактор записывал ссылку в `model.pictures.top`; в то же время `cropPhoto` рисовал отдельное изображение `.hero-photo img` из `model.crops[device].image`. Общий механизм изображений вставлял второй кадр `.section-media-frame` в секцию `top`, отсюда две фотографии и светлая рамка.

## Исправление
- Раздел `top` теперь имеет единственную область `.hero-photo`, дополнительных карточек быть не должно.
- Совместимость со старыми черновиками: выбранный `pictures.top` используется как главный портрет, пока администратор не назначит другие изображения для отдельных устройств.
- Из редактора разделов фото `top` выбирается глобально, а из фоторедактора — отдельно для устройства. При переходе с глобального на индивидуальный режим ранее выбранная фотография сохраняется на остальных устройствах.
- В оригинальном HTML встроен единственный fallback `img` (виден и в статическом GitHub Pages), устаревшие фоновые изображения у первого экрана и раздела «У волшебства есть голос» отключены.
- Изображения в D1/R2 и ревизии сайта не удаляются и не изменяются. Публикация сохраняет существующую отдельную ветку `preview`.

## Проверка
`npm test`: тесты `tests/hero-duplicate.test.js` проверяют совместимость модели, выбор глобального и индивидуального портретов и запрет второй карточки на первом экране. Визуальная проверка в браузере владельца требуется отдельно.
